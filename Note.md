In the customers table, customer_id is generated fresh for every order, so the same person can show up under several ids, while customer_unique_id identifies the actual person; to count customers I would use COUNT(DISTINCT customer_unique_id). The junction table is order_items: an order can contain many products and a product can appear in many orders, so this table resolves that many-to-many relationship, and it also ties each order to the seller who fullfils it. 

For customers to orders, the data is stricter than my diagram, because the line allows many orders per customer but each customer_id has exactly one order. The circle between orders and order_items is justified by the data, since 775 orders have no items at all. That also makes sense for the business (an order can exist before anything is added to it), so it is a real rule and not just a quirk of this sample.
